# Screen Specifications

Derived from `apps/web/src/app` (Next.js 15 App Router) on 2026-11-10. 40 `page.tsx` route files (including dynamic `[id]` routes and the `/settings` redirect) plus `not-found` and
error boundaries. Permission keys are from `packages/contracts/src/permissions.ts`; "nav" is the permission that shows the
sidebar item, "page" is what the page enforces through `PermissionGate`, and every API call is additionally authorized
server-side. Design tokens and components are in [design-system.md](./design-system.md).

Common to all `(app)` screens: authenticated shell (sidebar, top bar, organization switcher, notification bell, account
menu, theme toggle); `AuthGate` restores the session from the refresh cookie and redirects to `/login?next=…` (only same-origin
relative paths are honoured) or `/onboarding` when the user has no organization; the active organization is sent as
`x-organization-id`. Every list/detail has loading, empty and error-with-retry states unless stated otherwise. Verification
of each screen is **unit tests with mocked fetch plus the Playwright journeys**; no screen has been checked in a real
browser by this documentation pass, and responsive/dark-mode/accessibility audits have not been run.

## Public and authentication routes

| Route                    | Purpose                                                                                                | Permissions                                                          | States implemented                                                     | API used                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| `/` (`(marketing)`)      | Landing page: hero, six capability cards, trust points, sign-in / create-workspace links, theme toggle | public                                                               | static page (no data)                                                  | none                                                   |
| `/login`                 | Email + password, `next` redirect                                                                      | public                                                               | field errors, server error message (e.g. invalid credentials), loading | `POST /auth/login`                                     |
| `/register`              | Create account; optional `invitationToken` joins that org                                              | public                                                               | field + server errors, loading                                         | `POST /auth/register`                                  |
| `/forgot-password`       | Request reset link                                                                                     | public                                                               | always shows the same "if the account exists" confirmation             | `POST /auth/forgot-password`                           |
| `/reset-password?token=` | Set a new password                                                                                     | public                                                               | missing/invalid/expired token, success                                 | `POST /auth/reset-password`                            |
| `/verify-email?token=`   | Confirm email                                                                                          | public                                                               | verifying, success, invalid token                                      | `POST /auth/verify-email`                              |
| `/invite?token=`         | Preview and accept an invitation                                                                       | preview public; accept needs a signed-in account whose email matches | loading, invalid/expired/revoked, sign-in-or-register prompt, accepted | `GET /invitations/preview`, `POST /invitations/accept` |
| `/onboarding`            | Create the first organization (name, slug, industry, language `en`/`he`, time zone)                    | authenticated, no organization required                              | field + conflict (slug) errors                                         | `POST /organizations`                                  |

Language selection stores a value only; the interface is English-only and left-to-right.

## Cross-cutting UI behaviours

- **Notification bell** (top bar): unread count, list, mark read / read all. API: `/notifications`, `/notifications/unread-count`, `/notifications/:id/read`, `/notifications/read-all`.
- **Error boundaries**: `app/error.tsx`, `(app)/error.tsx` render `ErrorState`; `not-found.tsx` for unknown routes.
- **Rate limit / 402 / 403 handling**: API errors are mapped from the `{ error: { code } }` envelope to messages; `ENTITLEMENT_EXCEEDED` and budget stops show upgrade/budget messages.
- **Not present as screens**: activity center, deals/pipeline board, tasks, reports builder, platform admin, import/export, public customer chat, localisation, API-key management, MFA setup.
