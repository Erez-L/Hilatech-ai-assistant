# Internationalization (Hebrew / English)

The web app ships Hebrew (RTL) and English (LTR). Decision record: ADR-019 in `docs/architecture/decisions.md`.

## How the language is chosen

No locale in the URL. Per request, in order:

1. the signed-in user's saved preference (`PUT /users/me/preferences`, field `locale`);
2. the `hta_locale` cookie (set whenever the language changes);
3. `Accept-Language` (q-values respected, `iw` maps to `he`);
4. `en`.

`apps/web/src/i18n/config.ts` (`resolveLocale`) is pure and unit-tested. The root layout resolves the locale on the
server and renders `<html lang dir>`; `I18nProvider` also mounts the Radix `DirectionProvider` and the `@hilatech/ui`
strings. The switcher is in the user menu and on the login/register/landing pages (`LanguageSwitcher`). Changing it
updates the cookie and `<html>` immediately and PATCHes the profile when signed in; when signed out it sets a
`sessionStorage` flag and `LocaleSync` pushes the choice to the profile on the next sign-in (otherwise the saved
profile preference wins on a new device). The organization `locale` (onboarding / org settings) is a separate business
setting and does not change the UI language.

## Dictionary

- `apps/web/src/i18n/messages/en/<namespace>.ts` and `.../he/<namespace>.ts`; keys are `namespace.camelCaseText`.
- `he` is typed `Record<MessageKey, Message>`: a missing/extra key fails `tsc`.
- A message is a string with `{param}` placeholders, or a plural table `{ one, two?, other }` chosen by `params.count`
  (Hebrew uses `two`).
- Keep technical terms (webhook, API, cron, JSON) in Latin script inside Hebrew text.

Usage:

| Where                             | API                                                                            |
| --------------------------------- | ------------------------------------------------------------------------------ |
| Client component                  | `const t = useT(); t('team.memberCount', { count })`                           |
| Server component                  | `const t = await getT()` / `getLocale()` from `@/i18n/server`                  |
| Module-scope data (tables, enums) | `msg('key')` (a `Msg`), rendered with `t(ref)`                                 |
| zod schemas / thrown messages     | `vm('validation.key', params)`; `FormField` and `getErrorMessage` translate it |
| Enum values                       | `enumLabel(t, 'status', value)` (falls back to a humanized value)              |
| Inline elements in a message      | `rich(t, key, { name: <b/> }, params)`                                         |
| Numbers, dates, money             | `useFormat()` (`fmt.currency(value, code)`, `fmt.date`, ...)                   |

Pure helpers receive `t`/`fmt` as arguments; there is no global translator (avoids SSR cross-request bleed).
API error codes map to `errors.<CODE>`; other server messages go through a reverse lookup of the English dictionary
and are shown as-is when unknown.

## Adding or changing text

1. Add the key to `en/<ns>.ts` and `he/<ns>.ts` (same placeholders; plural tables need `other`).
2. Use `t()`/`msg()`; never write UI text in JSX, `aria-label`, `placeholder`, `title`, toasts or error props.
3. Run `pnpm --filter @hilatech/web test` and `tsc --noEmit`.

## RTL rules

- Logical Tailwind utilities only: `ms-/me-/ps-/pe-/start-/end-/text-start/border-s/rounded-s` (never `ml-/pr-/left-/text-left`).
  Exception: Dialog centring (`left-1/2`). Add `rtl-ok` to a line to allow a deliberate physical class.
- Directional icons (chevrons, arrows) mirror automatically (`styles.css`); add `data-no-flip` to opt out.
- Charts render in a `dir="ltr"` frame; tooltips follow the page direction.
- Inputs: free text `dir=auto`; email/url/number/password `dir=ltr` aligned to the end edge.
- Numerals, currency, dates and relative times come from `Intl` (`Asia/Jerusalem`); currency always uses the record's
  stored code (lead value in ILS shows `₪`, never `$`). The organization has a reporting currency setting; new leads
  default to it.
- Fonts: Inter + Heebo, self-hosted through `next/font/local` (no external requests).

## Tests

`apps/web/src/i18n/__tests__`: locale resolution, translate/plurals/fallback, validation message decoding, formatting,
en/he key + placeholder parity, hardcoded-text guard (`no-hardcoded-text.test.ts`, opt out with
`// i18n-ignore: reason`), physical-class grep (`rtl-classes.test.ts`). E2E: `apps/web/e2e/i18n-rtl.spec.ts`.

## Known gaps

- Server-generated text is English: notification title/body, analytics `tasks.reason`, some conflict/limit messages
  (known ones are mapped through the dictionary; unknown ones pass through).
- The dashboard API sums leads across currencies without conversion; the UI labels the total with the reporting
  currency, but mixed-currency orgs get an unconverted sum (backend change needed).
- The server preferences notification shape differs from the web mirror.
- Transactional email templates and AI prompts/assistant replies are not localized by this work.
- Hebrew copy was machine-drafted and has not had a native-speaker review.
- Only two locales; adding one means a new `messages/<code>` folder plus `LOCALE_META`.
